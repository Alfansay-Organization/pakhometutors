Debug by Changing One Thing at a Time

When a program fails, changing five things at once hides which fix worked — or which new bug you introduced. Controlled debugging means one hypothesis, one change, one test.

A practical loop

  1. Read the exact error message or wrong output
  2. Form one guess (“the loop never stops” / “the variable is empty”)
  3. Add one print or change one line
  4. Run again and compare
  5. Keep or undo that change, then continue

Rubber-duck explaining the code aloud often surfaces the mistake before you edit anything.
